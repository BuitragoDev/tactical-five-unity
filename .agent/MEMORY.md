## 2. Goal & core mechanics (as built)

- Simulate an NBA-like franchise career: 30 teams, 82-game season (Oct 22 → mid-April), Play-In, Playoffs (best-of-7), draft, awards, records, and infinite seasons with aging/progression.
- Player is GM, not a coach/player: picks lineups, manages contracts/salary cap, finances, staff, training, morale, and hits "advance day".
- Match outcomes decided by `GameSimulator` (possession-based, attribute-driven).

## 5. Key architectural decisions & reasons

| Decision | Reason (observed/deduced) |
|---|---|
| Single scene + `UIDocument` screens, `ScreenManager` toggling `SetActive` | All UI in one place; cheap navigation; controllers rebuild in `OnEnable` |
| `UIScreenController` base class for all 47 controllers | Centralizes full-screen, chrome (Header/Sidebar), nav, cursors, config modal — removed ~60% boilerplate |
| SQLite as the save/state store | Sim data is relational (teams/players/games/stats); template DB gives fast, consistent new games; avoids JSON save parsing |
| Static utility classes for simulation rules | Stateless, testable helpers; controllers call them directly |
| No event bus; DB-messages + static hand-offs | Simplest possible decoupling for a single-player sim; avoids async complexity |
| `overall` always recomputed from 11 attributes (cap `potential`) | Single source of truth for ratings; training/aging stay consistent |
| **`schema_migrations` + `PRAGMA user_version`** for data migrations; column-presence `ALTER TABLE` for schema | Migrations live with the slot (delete slot = clean state); additive schema keeps old saves openable |
| Background work via `Task.Run` + WAL + `AsyncLocal` ambient connection (`RunInBackground`/`RunInBackgroundAsync`) | Heavy batches (injuries/physical, `StartNewSeason`, AI trades) off the main thread; match sim stays main-thread (fast, stable) |
| Cap constants duplicated in `TradeHelper` and `league_settings` (seeded) | `TradeHelper` is source for UI; DB copy exists for potential runtime changes (+5%/season applied to DB row) |
| **Minutos de rotación en `team_lineup.rotation_minutes`, no en `players`** | La convocatoria es la fuente de verdad (Quinteto y Rotación comparten `team_lineup`); al cambiar de equipo o irse a FA los minutos no viajan con el jugador. El `-1` es el único centinela de "automático" — `0` es un valor real (0 minutos). |
| **Imágenes de equipos por overlay (`TeamImages`)** | Los logos/pabellones originales viven en `Resources` (solo lectura, empaquetados); las versiones personalizadas se guardan en `persistentDataPath/TacticalFive/Custom/{scope}/...` (`Logos/{size}`, `Arenas`, `PlayerPhotos`) y tienen prioridad al cargar. **Lógica de ámbitos en `CustomScopes`** (`Active`, `ScopeRoot`, `HasCustom`, `CopyCustom`, `DeleteScope`, migración); `TeamImages` la usa para `Logos`/`Arenas`. **Ámbitos por partida:** `scope` = `template` (lo que edita el Editor) o `save_{n}` (partida). `InitTemplateSession()` fija `template`; `InitSaveSlot(n)` fija `save_{n}` y, si la partida es nueva (o antigua sin carpeta), hace snapshot copiando `template → save_{n}` (`CopyCustom`, que siempre crea la carpeta destino). Al borrar partida (`GameSaveManager.DeleteSave`) se borra `save_{n}`. Migración una vez: si existe la carpeta global antigua `Custom/{Logos,Arenas}` se mueve a `Custom/template/`. RESETEAR solo borra el ámbito `template` (`ClearCustom`); las partidas existentes conservan las suyas (las originales nunca se tocan). Todas las cargas de `Teams/Logos`/`Arenas` pasan por `TeamImages` (`Logos`/`Logo`/`Arenas`/`Arena`, que usan el ámbito activo); para leer varias partidas a la vez existe `LogosFor`/`LogoFor`/`ArenasFor`/`ArenaFor(scope, ...)` (la caché está indexada por ámbito), y la pantalla Cargar Partida usa `SlotScope(slot)` = `save_{n}` si tiene carpeta, si no `template`. |
| **Foto de jugador por ámbito (`PlayerPhotoHelper`)** | La foto custom se guarda en `Custom/{scope}/PlayerPhotos/{id}.png` (mismo sistema de ámbitos/snapshot/borrado que logos/pabellones) y tiene **prioridad sobre `Resources`** al cargar (`Load`): custom → `Resources/{id}` → `Resources/{photoField}` → `PlayerPhotos/{slot}` → `PlayerPhotos/{id}` → `default`. El Editor la cambia en la pestaña JUGADORES (`ValidatePhotoFile` PNG 64–2000 px + `SetPhoto`). |

## 6. Confirmed assumptions

- `overall` is intended to be the mean of 11 attributes capped by `potential`, but current code uses integer division and mentoring does not recalculate it; verify this invariant before relying on post-mentoring ratings.
- `PlayerData.id` manual (seed 1..~600) — stable across cloned slots.
- `league_settings` seeded from `TradeHelper` constants + `bi_annual=5.1M`; `StartNewSeason` raises all caps +5%.
- Employee `reputation` (1–5) drives ticket multiplier and renovation discounts (not `skill`; `EmployeeData` has no `skill` field).
- FA external signings have **no Bird Rights** (`birdMax=0`); exceptions apply by apron when over cap.
- NT-MLE usage sets `first_apron_hard_capped=1`.
- Offers mature after 7 days (`day_sent + 7`); acceptance = `Random(1,101) <= acceptScore`.
- Contract options (TO/PO) are mutually exclusive; if set, `guaranteed_years = max(0, offer_years − 1)`. Persisted on `players`/`offers` (`guaranteed_years`, `has_team_option`, `has_player_option`). Renewal & FA offer modals toggle them; `ProcessMaturedOffers.FormatContractYears` shows them in inbox messages.
- `players.last_team_id` tracks the last team a player played for (set at seed/sign, kept when going to FA via option decline or contract expiry). `IsOwnRecentFA(p, teamId)` = `team_id==0 && last_team_id==teamId && seasons_with_team>0` → used to grant **Bird rights** on re-sign (`GetMaxOfferBreakdown(isFromSameTeam:true)`) and to re-attach the player on accepted re-sign offers. `NewSeasonController` shows a re-sign modal for declined player options (deferred offer, matures in 7 days).
- **Sign-and-trade de FA propio** (`MarketController.ProcessSATrade`): sección "FA RECIENTES (BIRD RIGHTS)" en el panel de traspaso; firma (Bird) + traspaso inmediato → dos `TradeData` (`free_agent` + `sign_and_trade`); receptor bajo hard cap del 1er apron. `TradeHelper.ValidateTrade`/`EvaluateTrade` aceptan `teamASignSalaries`/`teamBSignSalaries` (salario nuevo firmado; no descuenta roster/nómina del que firma). La IA propone S&T por el FA propio del usuario (`GenerateAITradeOffersForPlayer`, resuelto en `ShowNextPendingTradeOffer`) y `pendingSATIds` evita que la IA lo fiche mientras la oferta está pendiente. El S&T de jugador entrante expirante (toggle en `ShowTradeResult`) se mantiene.
- **Trade Deadline con evento real:** `OnActionClicked` intercepta el btnAction el 7 de febrero: modal "DEADLINE DAY" (IR AL MERCADO / CERRAR, una vez por temporada vía `_deadlineDayModalShown` + `_deadlineModalSeasonId`). No avanza la fecha. Rush IA durante Feb 1-8: `ProcessAITransfers` cooldown 3-5 días (`IsDeadlineWeek`), contenders (`IsTeamContender`, top 4 conferencia) ofrecen picks extra, títulos de ofertas IA con prefijo `[DEADLINE]`. Badge `⏳ ÚLTIMOS X DÍAS` en header del Market (`DeadlineCountdownBar` en `Market.uxml`). `DashboardController.ShowDeadlineDayModal`, `IsFeb7OfYearEnd`.
- **Hall of Fame / dorsales retirados:** inducción si `ShouldInduct` (1 anillo O 1 FMVP O 30k pts O 15k reb O 10k ast); `TryInductIntoHallOfFame` en `StartNewSeason`; ~100 leyendas vía `HallOfFameSeeder` (`player_id=0`); `retired_numbers` seed 53+17, `AssignJerseyNumber` reserva dorsales. Pantallas: Palmares (panel HOF) + EndSeason; Dorsales.
- **Pantalla ROTACIÓN (`GameScreen.Rotation`, submenu PLANTILLA tras QUINTETO):** reparto manual de los 240 minutos del partido entre los 12 convocados (`RotationController`, `UI/Screens/Rotation/`). Persistencia en **`team_lineup.rotation_minutes`** (`-1` = automático, `0..48` = fijo); `PlayerData.rotation_minutes` es **transitorio `[Ignore]`** rellenado por `GetActivePlayers` para que el simulador lo use como `target_minutes` (`PrepareRotationMetadata`: si es `< 0` aplica la heurística `GetTargetMinutes`; si está configurado es **vinculante**, con suelo de **2 min** —`0` se respeta: no juega— y sin penalización por fatiga). **Los minutos configurados se respetan de verdad** gracias a `GameSimulator.PickSubstitution` (helper puro; sale el que más se pasa de su plan, entra quien tiene minutos pendientes ponderando encaje posicional ×1.0/×0.85/×0.6; nunca reingresa a quien agotó su plan si hay relevos con minutos; nunca deja la pista sin interiores) y a ventanas de substitución densas cada 1,5' solo para ese equipo (el rival y los partidos IA-IA mantienen el calendario antiguo y la regla de estrellas por minutos globales). Si nadie tiene minutos pendientes no hay cambios (los de pista completan cuando la suma < 240); si el total configurado es 0, el equipo vuelve al reparto automático. SUG. = `GameSimulator.GetSuggestedMinutes`. **Solo el equipo del usuario usa minutos configurados; la IA, la G-League y el All-Star siguen con la heurística y el calendario de cambios antiguo.** La moral post-partido usa ese `target_minutes` como minutos esperados (si es 0, la tabla fija por rol). ## 7. Things that must NEVER change without reviewing the rest of the project

1. **`overall` semantics** (mean of 11 attrs, cap by potential) — affects seed, training, aging, migration, drafting, AI evaluation, standings sorting.
2. **Cap/apron constants location** (`TradeHelper`) and their +5%/season growth — used by dozens of screens and validations.
3. **`ScreenManager.GoTo` contract** (mode handling, `ShowOnly` SetActive) — every controller depends on it.
4. **`GameResultCache.Clear()` at day start** — forgetting it corrupts the results flow.
5. **Slot/DB path layout** (`TacticalFive/saves/save_{n}.db`, `template.db`, `saves.json`, `PlayerPhotos/{slot}`) — game saves and delete logic depend on it.
6. **`MessageData.sender_type` semantics** (0 system / 1 player / 2 news) — used for filtering/icons.
7. **`player_season_stats` + `monthly_awards` dual creation path** (CreateTable AND raw SQL) — any schema change must update both.
8. **`phase` state machine** (preseason→regular→playin→playoff→finished) — drives dashboard, playoffs, awards. **La G-League NO participa: su postseason se gobierna solo por datos (`game_type` gleague/gleague_playoff).**
9. **The config modal in the base** — `UIScreenController.InitConfigModal`; the 12 controllers that override `RegisterCallbacks()` without `base` don't get it — keep new screens on the base path.
10. **`schema_migrations` / `PRAGMA user_version`** — data migrations are named and stored in the DB (per slot); don't reintroduce global `PlayerPrefs` flags.
11. **Background DB work** — helpers run on the ambient (`AsyncLocal`) connection inside `RunInBackground`/`RunInBackgroundAsync`; don't touch `_db` off the main thread.
12. **Codificación de ids G-League en `games`** — home/away = id filial + 1000 (`GLeagueHelper.GAME_TEAM_ID_OFFSET`); cualquier query nueva que lea partidos GL debe descodificar con `DecodeGlTeamId`; los prospectos simulan con id +500000 (`PROSPECT_ID_OFFSET`). No "limpies" estos offsets creyendo que son bugs.
13. **`team_lineup.rotation_minutes`** — centinela `-1` = automático; la heurística del simulador (`GetTargetMinutes`) es el fallback. Un valor `≥ 0` es **vinculante** para el equipo del usuario (`fixed_minutes` → `PickSubstitution`), con suelo de 8 min y `0` = no juega. Si cambias el umbral, actualiza `PlayerData.rotation_minutes` (inicializador `-1`), `RotationController.Effective`, `PrepareRotationMetadata`, `PickSubstitution` y `DatabaseManager.SetLineupMinutes`. Los sliders de ROTACIÓN nunca permiten pasar de **240 min** en total (`RotationController.RefreshSliderLimits` → `CustomSlider.MaxValue`): con el reparto completo o excedido cada barra solo puede bajar. **Al crear la partida** (CONTINUAR en Preseason) se siembra la convocatoria (`EnsureLineupSeeded`) y los minutos quedan en automático; en ese estado la pantalla muestra el **reparto automático de 240** (`RotationPlanner.AutoAssign`, suelo 2 = `MIN_FIXED_MINUTES`) y lo fija al primer toque de slider. Las sugerencias por jugador (`GetSuggestedMinutes`) NO suman 240: **la referencia de la pantalla es la cuota de 240** (`RotationPlanner.AutoAssign` sobre los ideales; columna SUGERIDO y ± contra esa cuota, tooltip con el ideal bruto). Tabla de objetivos (`GetTargetMinutes`): titular ≥90 → 40, ≥85 → 34, ≥80 → 33, ≥75 → 26, <75 → 20; suplente ≥90 → 32, ≥85 → 28, ≥80 → 22, ≥75 → 14, <75 → 12; `UltimoRecurso` → 2 (`MIN_FIXED_MINUTES` = 2). El reparto de 240 usa una **rotación corta de 10** (`RotationPlanner.ROTATION_SIZE`: solo los 10 mejores objetivos reparten; el fondo queda en el suelo). El rol se asigna por media con `PlayerRoleRules.FromOverall` (seed, draft y migración `role_from_overall`). **Antes de simular** el Dashboard valida la rotación del equipo del usuario (`RotationPlanner.Evaluate`): es válida si no hay jugables, si está **todo en automático** (todos ≤0) o si suma **240 exactos y válidos**; si no, muestra el aviso ROTACIÓN INCOMPLETA (IR A ROTACIÓN / ASIGNAR AUTOMÁTICAMENTE = `DatabaseManager.AutoAssignRotationMinutes`) y en simulación rápida la pausa. Solo cuentan los convocados jugables (lesionados/G-League fuera).
14. **`PlayerData.rotation_minutes` es `[Ignore]`** (transitorio): nunca añadas una columna `rotation_minutes` a `players` sin revisar quién la rellena (`DashboardController.GetActivePlayers`).
15. **Histórico de carrera por `player_id`, nunca por nombre** (`historical_player_stats`): `>0` jugador real, `-1` leyenda del seeder (intocable), `0` fila antigua sin dueño (solo se adopta en la migración si el nombre identifica a un ÚNICO jugador). Reglas puras en `HistoricalStatsRules` (`RowForPlayer`/`CanAdopt`/`IsLegendRow`). No vuelvas a resolver carreras por nombre: los pools de nombres solapan con las leyendas (SEA-06).
16. **`playoff_series` se escribe al cerrar cada serie** (`PlayoffsGenerator.AdvancePlayoffSeries`, idempotente por `manager_id+season_id+label`): `games` se purga en el rollover, así que es la **única** fuente de rivalidades (play-in excluido). Agregaciones puras en `RivalryHelper`/`DynastyHelper`; dinastías/prestige se derivan de `season_records` (no añadas columnas a `teams`).
17. **El All-Star no persiste `player_game_stats`** (`SIM-14`): las convocatorias viven en **`all_star_roster`** (`SaveAllStarRoster` en el partido de las estrellas) y son la única fuente de `GetAllStarAppearances` (Palmarés) y de los `award_type="all_star"` de la trayectoria. Las columnas `season_records.all_star_pg..c` son legado sin uso.
18. **Mercado de buyout:** al rescindir, el jugador queda FA con **contrato a 0 y salario = mínimo** (`waived_game_day` = jornada de la rescisión) y firma **por el mínimo y 1 año** (`BuyoutMarketRules.ContractYears`); la IA le firma **en cuanto pasa esa jornada y solo si tiene 75+ de media** (`BuyoutMarketRules.MinOverall`; por debajo queda en agentes libres y decide el mercado general) (destino = ranking contender > balanced > rebuild, menos jugadores en su posición, mejor plantilla y prestigio; **sorteo ponderado entre los 3 mejores postores**, `RankDestinations`/`PickSuitor`, con noticia) y **los fichajes IA usan `CanAISignExternal` (espacio → MLE → mínimo) y fijan el salario nuevo** (nunca heredan el viejo). **Al expirar, el precio pedido sube a su valor de mercado** (`TradeHelper.MarketValueByOvr`) para que no quede barato para siempre, la renovación IA va a mercado si está **3× por debajo** (`ShouldRenewAtMarket`, sin el tope no-Bird → máximo por experiencia) y `ProcessOwnFreeAgentResignings` permite al equipo con **Bird rights** re-firmar a sus FA recientes por encima del tope (límite 2º apron). La marca se limpia al firmar y en el rollover; el equipo que le cortó sigue pagando el resto como `dead_money`.
19. **Hitos de carrera (E1):** `player_milestones` (una fila por hito y `player_id`, sobrevive al retiro). La carrera se calcula como **histórico (`historical_player_stats`, por `player_id`) + temporada en curso (todos los tipos menos All-Star) + honores** (`rings/finals_mvps/season_mvps` y All-Star de `all_star_roster` + `allstar_appearances_seed`) en `DatabaseManager.BuildCareerTotals`. `MilestoneService.EvaluateDay` corre cada día antes del motor de narrativa, registra lo nuevo y emite **una noticia agrupada por jugador** (`NewsType.LEGADO`); la **primera vez por partida** hace una línea base silenciosa (`milestones_baselined`). El hilo `hito_alcanzado` (por jugador, dura el día) **no duplica la noticia**: solo da badge y efecto. El HOF induciendo con **10× All-Star o 3× MVP** es parte de esta feature.

## 9. Audit warnings that must remain visible

- `FastSimRoutine` yields while the day transaction is open; do not describe FastSim as fully atomic until the boundary is fixed.
- `BuildTemplateDatabaseInBackground` temporarily swaps the shared `_dbField` from a worker thread; isolate template generation before allowing concurrent editor/save operations.
- `StartNewSeason` currently skips rookies in its progression loop.
- Team ratings include injured players and the local bonus is gated by the user's-home flag in the current Dashboard path.
- Luxury-tax records are negative while expense aggregation treats expense amounts as positive.
